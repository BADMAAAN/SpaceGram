# Qwengram

**Экспериментальный неофициальный Telegram-клиент для iOS с открытым исходным кодом.**

Qwengram исследует, каким может быть клиент с большим контролем со стороны пользователя, встроенным ИИ, полезными утилитами и удобным интерфейсом для тех, кому нужны дополнительные возможности Telegram. Он использует инфраструктуру и протокол Telegram через Telegram-iOS и не создаёт новую сеть обмена сообщениями.

Архитектура проекта — Telegram-iOS плюс собственный слой Qwengram. Используемые унаследованные реализации находятся в `Qwengram/Enhancements`; Nagram остаётся источником происхождения кода, а не архитектурным upstream. Проверенное по исходникам состояние описано в [аудите проекта](QWENGRAM_PROJECT_AUDIT.md).

## Зачем нужен Qwengram

Telegram уже предоставляет мощную платформу для общения. Qwengram исследует, как дополнить её настройками приватности, помощью ИИ, утилитами, действиями с сообщениями и возможностями для опытных пользователей.

Ближайший приоритет — качество: собрать, подписать, установить и проверить существующий MVP на реальном iPhone, исправить обнаруженные проблемы и лишь затем расширять основные функции.

## Архитектура

```text
Telegram-iOS upstream
    ↓
Qwengram: функции, сохранённые расширения, точки интеграции
```

| Слой | Назначение |
| --- | --- |
| Telegram-iOS | Исходная основа приложения и платформы, включая интеграцию с Telegram. |
| Сохранённые расширения | Используемые реализации в Qwengram; имена совместимости и ключи хранения сохранены. |
| Qwengram | Независимый продуктовый слой, разрабатываемый в этом репозитории. |

Собственный код Qwengram следует размещать преимущественно в `Qwengram/`. Происхождение кода Nagram должно оставаться понятным: массовое переименование или переписывание скрывает историю кода и усложняет обновление из исходных проектов.

Неизбежные точки интеграции с Telegram/Nagram отмечаются `// MARK: QWENGRAM` и перечисляются в [описании точек интеграции](Qwengram/QWENGRAM_HOOKS.md). Они связывают навигацию настроек и действия с сообщениями с контроллерами Qwengram.

## Настройки Qwengram

Отдельный пункт Qwengram в настройках приложения открывает страницу собственных настроек. Сейчас на ней доступны:

| Настройка | По умолчанию | Текущее поведение |
| --- | --- | --- |
| `qwengramEnabled` | `true` | Сохраняет значение «Qwengram Enabled». Пока не отключает все точки входа и функции Qwengram. |
| `botsHubEnabled` | `true` | Определяет доступность пункта «Open Bots Hub» на этой странице. |
| `qwenModel` | `qwen-plus` | Хранит идентификатор модели, который задаётся в настройках ИИ. |

Эти параметры хранятся локально в `UserDefaults.standard`. Слой `SettingsSignal/` передаёт начальные значения переключателей и отслеживает `UserDefaults.didChangeNotification`, отбрасывая повторяющиеся значения. Интерфейс обновляется без периодического опроса.

В разделе AI открывается **Qwen Provider**. **Ghost Mode**, **Message History** и **Media Archive** пока представлены неактивными пунктами «Coming soon». Логика глобального включения функций ещё может измениться; эти переключатели нельзя считать универсальным средством отключения обработки данных.

## Bots Hub

Сейчас Bots Hub — внутренний каталог инструментов и помощников Qwengram, а не универсальная система запуска удалённых ботов.

| Категория | Текущие пункты |
| --- | --- |
| AI | Qwen Assistant, Summarizer, Translator — работают. |
| Media | Media Tools — неактивная заглушка. |
| Utilities | QR Tools — работает; Reminders — неактивная заглушка. |
| Custom | В интерфейсе называется «My Bots»; Add Bot пока неактивен. |

Каталог хранит описания инструментов: название, категорию, доступность и другие поля. Активные пункты открывают локальные контроллеры Qwengram. Выполнение удалённых ботов и добавление собственных ботов пока не реализованы.

## QR Tools

Откройте **Qwengram Settings → Open Bots Hub → QR Tools**, введите текст и нажмите **Generate QR**. Изображение появится на том же экране. При пустом вводе или неудачной генерации выводится сообщение об ошибке.

Генерация полностью выполняется на устройстве через `CIQRCodeGenerator` из CoreImage, которому передаётся текст в UTF-8. Сетевой запрос не требуется. Текущая версия создаёт и показывает QR-коды; сканера и отдельного сценария экспорта в ней нет.

## Интеграция с Qwen

В слое ИИ разделены типы сообщений, ошибки, интерфейсы провайдеров, доступ к Keychain и реализация Qwen:

- `QwengramAIMessage` описывает сообщения с ролями system, user и assistant.
- `QwengramAIProvider` предоставляет непотоковый метод `generateText`.
- `QwengramAIStreamingProvider` предоставляет `streamText` и отменяемую задачу `QwengramAIStreamingTask`.
- `QwengramQwenProvider` реализует оба интерфейса с помощью `URLSession`.

Текущая реализация обращается к OpenAI-совместимому API chat completions сервиса Alibaba Cloud Model Studio / DashScope. В исходном коде задан следующий адрес по умолчанию:

```text
https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions
```

Модель по умолчанию — **`qwen-plus`**. В **Qwengram Settings → AI → Qwen Provider** можно указать другой идентификатор модели. Адрес API можно передать при создании провайдера в коде; в текущем интерфейсе нет редактора адреса или выбора провайдера.

Запросы содержат сообщения в JSON и используют Bearer-аутентификацию. Qwen Assistant получает потоковые ответы, а Summarizer и Translator — обычные ответы целиком. Интерфейсы разделяют обязанности компонентов, но выбор между несколькими ИИ-провайдерами пока не реализован.

## Безопасность API-ключа

Пользователь указывает собственный API-ключ Qwen. Он сохраняется в iOS Keychain, а не в исходном коде или обычных UserDefaults. Для записи используется `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`. В проверенных путях Qwengram AI нет намеренного вывода ключа в журналы.

На странице настроек есть поле ввода пароля, **Save**, статус настройки и **Remove API Key**. При сохранении модели пустое поле ключа позволяет оставить существующий ключ без изменений. Статус «Configured» означает наличие сохранённого ключа, а не успешную проверку соединения с сервисом.

| Учётные данные | Назначение |
| --- | --- |
| Telegram API ID / API hash | Настройка сборки и идентификация приложения при работе с Telegram. Тестовый процесс получает их из секретов репозитория. |
| Qwen API key | Необязательные ИИ-функции во время работы Qwengram. Пользователь вводит ключ в приложении. |

Это разные учётные данные. Не размещайте их реальные значения в исходном коде, публичной документации или отчётах об ошибках.

## Qwen Assistant

1. Откройте **Qwen Assistant** из Bots Hub или выберите **Ask Qwen** на локальном экране работы с сообщением.
2. Напишите или отредактируйте текст и нажмите **Send**.
3. Контроллер проверит, что текст не пуст, ключ сохранён, а модель указана.
4. В Qwen будет отправлен текущий диалог из памяти, включая предыдущие сообщения пользователя и помощника.
5. Ответ будет дополняться по мере поступления текста.
6. **Stop Generating** остановит активный поток. Уже полученный текст останется в диалоге; пустой блок ответа будет удалён.

Обработчик закрытия контроллера также останавливает активную генерацию. Ошибки сети, HTTP, разбора данных и пустые ответы показываются пользователю.

Это временный текстовый диалог, а не постоянное хранилище переписки. Вложения и сохранение истории не реализованы. Автоматического сокращения контекста в контроллере нет, поэтому длинные сеансы могут упираться в ограничения провайдера.

## Summarizer

Откройте **Summarizer**, вставьте или введите текст, проверьте его и нажмите **Summarize**. При переходе из сообщения этот же ввод заполняется заранее.

Инструмент использует настроенную модель Qwen и ключ из Keychain, отправляя текст вместе с инструкцией для краткого изложения. Автоматического просмотра чатов нет. Результат появляется после завершения непотокового запроса.

Ввод и результат хранятся в памяти контроллера. Запуск нового запроса очищает предыдущий результат. Постоянной истории и кнопки Stop Generating на этом экране нет.

## Translator

Откройте **Translator**, введите или проверьте текст, выберите язык перевода и нажмите **Translate**. Для исходного языка всегда указано **Auto Detect**: модель определяет его по отправленному тексту, без отдельного локального этапа распознавания.

Текущий список языков перевода: **английский, русский, китайский, испанский, немецкий, французский, японский и корейский**. Изначально выбран английский.

Перевод использует существующий провайдер Qwen, настроенную модель и ключ из Keychain. Ввод и результат остаются в памяти; новый запрос очищает предыдущий результат. Ответ поступает целиком, кнопки Stop Generating на этом экране нет.

## Интеграция с сообщениями Telegram

```text
Удержание подходящего обычного текстового сообщения
    ↓
Qwengram AI
    ↓
Локальный экран просмотра и выбора действия
    ↓
Ask Qwen / Summarize / Translate
    ↓
Проверка или редактирование подставленного текста
    ↓
Явное нажатие Send / Summarize / Translate
```

Точка интеграции проверяет, что выбрано одно сообщение, текст содержит непробельные символы и в сообщении нет секретных медиа. Внешнее условие исключает контент с истёкшим сроком действия. При этом явного запрета для всех текстовых сообщений из секретных чатов в проверенном коде нет, поэтому обещать полное отсутствие этой функции в секретных чатах было бы неверно.

**Открытие меню Qwengram AI не отправляет содержимое сообщения ИИ-провайдеру.** Выбор инструмента также только открывает контроллер с заполненным вводом. Запрос начинается после нажатия кнопки выполнения в самом инструменте.

Эта граница намеренно отделяет локальный просмотр от внешней обработки ИИ. Экран передаёт инструменту текст, а не автоматически загружает всю переписку.

## Потоковые ответы и отмена

Провайдер Qwen запрашивает Server-Sent Events (SSE). Он буферизует поступающие байты, собирает события `data:`, извлекает фрагменты `delta.content` и считает маркер `[DONE]` признаком успешного завершения. Закрытие соединения без этого маркера обрабатывается как неожиданное завершение потока.

Последовательная очередь состояния согласует разбор данных, отмену и завершение. Защитный флаг не позволяет повторно вызвать итоговый callback. При завершении очищаются буферы, отменяется задача и закрывается сессия потока.

Контроллер помощника отслеживает идентификатор генерации. При остановке он меняется, поэтому callbacks от прежней генерации не могут изменить текущий диалог. Интерфейс обновляется в главной очереди с проверкой видимости контроллера. Эти механизмы присутствуют в исходном коде; их проверка на реальном устройстве остаётся частью работы над MVP.

## Модель приватности

| Операция или данные | Текущая граница обработки |
| --- | --- |
| Открытие меню ИИ или выбор инструмента | Локальный просмотр и навигация без запроса к ИИ. |
| Выполнение ИИ-действия | Переданный текст и соответствующий контекст диалога с помощником отправляются в Qwen. |
| API-ключ Qwen | Хранится в iOS Keychain и используется для аутентификации запросов. |
| Ввод, диалоги и результаты ИИ | Хранятся в памяти текущих контроллеров; постоянной истории нет. |
| Создание QR-кода | Локальная обработка CoreImage без обращения к сети. |
| Интеграция с исходным клиентом | Небольшие документированные точки входа в контроллеры Qwengram. |

Это описание проверенных функций Qwengram, а не обещание полностью автономного или «абсолютно приватного» Telegram-клиента. Telegram продолжает обращаться к своей инфраструктуре, а необязательные ИИ-функции — к Qwen. Хранение в памяти не определяет политику внешнего провайдера и не гарантирует немедленного стирания данных из памяти.

## Медиа и временный контент

Управление обычными медиафайлами, кешем и архивом входит в планы. **Media Tools** и **Media Archive** пока являются заглушками, а не работающими средствами архивирования.

Запланированная работа касается обычных медиа. Обход ограничений на однократный просмотр, самоуничтожение или другие механизмы защиты временного контента здесь не заявляется как возможность Qwengram.

## Текущий процесс разработки для iPhone

```text
Разработка на Windows
    ↓
Git push
    ↓
Репозиторий GitHub
    ↓
macOS-раннер GitHub Actions
    ↓
Xcode + Bazel
    ↓
IPA для iPhone ARM64
    ↓
Скачивание на Windows
    ↓
Личная подпись и установка вне App Store
    ↓
Проверка на физическом iPhone
```

Для повседневного редактирования кода достаточно Windows; владеть Mac не обязательно. Раннер GitHub на macOS предоставляет инструменты Apple для компиляции iOS-приложения, включая Xcode. Подпись и установка выполняются отдельно.

Ручной [процесс Qwengram iPhone Test Build](.github/workflows/qwengram-ios-test.yml) получает код из `qwengram/main`. При успешной сборке он публикует **Qwengram-iPhone-test** с файлом `Telegram.ipa`. Также предусмотрен артефакт с журналом неудачной сборки.

Настройка и имена необходимых секретов репозитория описаны в [инструкции по тестовой сборке](Qwengram/IOS_TEST_BUILD.md). Неподписанный IPA нельзя установить напрямую; наличие артефакта не подтверждает успешную подпись, установку или работу приложения.

## Текущее состояние разработки

Qwengram активно разрабатывается. Порядок работы следующий:

1. **Сначала:** собрать, подписать, установить и проверить существующий MVP на реальном iPhone.
2. **Затем:** исправить ошибки, проявившиеся на устройстве, и стабилизировать текущие инструменты.
3. **После этого:** расширять основные функции приватности, истории и работы с медиа.

Наличие реализации и файла workflow не означает, что полный цикл проверки на реальном устройстве уже пройден.

## Принципы разработки

По возможности изолируйте код Qwengram, сводите изменения исходных проектов к минимуму и документируйте неизбежные точки интеграции. Сохраняйте возможность обновления и перебазирования, не скрывая происхождение унаследованного кода.

Изменения должны быть целевыми, а реализованные функции — чётко отделены от заглушек. Проверяйте участки, чувствительные для приватности, особенно переход от локального просмотра к сетевому запросу. Прежде чем резко расширять объём функций, проверяйте текущий MVP. Английскую и русскую документацию следует поддерживать согласованно.
